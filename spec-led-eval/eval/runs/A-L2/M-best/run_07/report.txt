  Strategy: replace each named fact's body with `{}` (no constraint),
  then re-run Alloy. Each listed assertion should now FAIL on the
  mutated model. If it still PASSes, the assertion is vacuous and

  - MUTATE F_LeastPrivilegeOutcome  → runs/A-L2/mutated_F_LeastPrivilegeOutcome.als
    rationale: F_LeastPrivilegeOutcome is the load-bearing fact that maps disallowed (role,kind) pairs to a Denied outcome. Clearing it removes the deny-side enforcement; the injection forces an Operation whose (caller.role -> kind) is not in PermMatrix.Allowed yet whose outcome is OK, directly contradicting LeastPrivilege's 'outcome=OK implies in matrix' clause.
    expected to FAIL: LeastPrivilege, FR_001_AuthRequired, FR_002_CustomerLeastPriv, FR_023_ComplianceNoWrite
      - LeastPrivilege: FAIL (expected)
      - FR_001_AuthRequired: FAIL (expected)
      - FR_002_CustomerLeastPriv: FAIL (expected)
      - FR_023_ComplianceNoWrite: PASS (vacuous?)

  - MUTATE F_AppendOnlyAuditEntries  → runs/A-L2/mutated_F_AppendOnlyAuditEntries.als
    rationale: F_AppendOnlyAuditEntries forbids two AuditEntry atoms recording the same (application, prev, new) triple — the structural encoding of 'no duplicates, no mutation through replacement'. Removing it lets the model invent a duplicate entry, and the injection forces exactly that, which the AppendOnly assertion is supposed to catch.
    expected to FAIL: AppendOnly, FR_018_AuditAppendOnly, FR_019_ExactlyOnePerChange
      - AppendOnly: FAIL (expected)
      - FR_018_AuditAppendOnly: FAIL (expected)
      - FR_019_ExactlyOnePerChange: FAIL (expected)

  - MUTATE F_CustomerOwnershipForGet  → runs/A-L2/mutated_F_CustomerOwnershipForGet.als
    rationale: F_CustomerOwnershipForGet enforces that a customer's GetApp against an application they don't own is denied (matching the contract's 404 no-existence-leak rule). Clearing it allows successful cross-customer reads; the injection produces a customer Operation with OK outcome on someone else's application, violating OwnershipBasedAccess.
    expected to FAIL: OwnershipBasedAccess, FR_020_CustomerOwnAppsOnly
      - OwnershipBasedAccess: FAIL (expected)
      - FR_020_CustomerOwnAppsOnly: FAIL (expected)

  - MUTATE F_OneInFlightPerCustomer  → runs/A-L2/mutated_F_OneInFlightPerCustomer.als
    rationale: F_OneInFlightPerCustomer is the Alloy encoding of the partial unique index idx_one_in_flight_per_customer. Clearing it lets two in-flight applications coexist for the same customer; the injection forces such a pair, which the FR-008 assertion explicitly forbids.
    expected to FAIL: FR_008_OneInFlight
      - FR_008_OneInFlight: FAIL (expected)

  - MUTATE F_DecideRequiresAssignedOfficer  → runs/A-L2/mutated_F_DecideRequiresAssignedOfficer.als
    rationale: F_DecideRequiresAssignedOfficer ties a successful OpDecide to the application's assigned officer (matching the conditional UPDATE … WHERE assigned_officer_id=?). Clearing it lets a non-assigned officer decide; the injection produces an OpDecide with OK outcome whose caller is not the assigned officer, breaking FR-013.
    expected to FAIL: FR_013_OnlyAssignedDecides
      - FR_013_OnlyAssignedDecides: FAIL (expected)

  - MUTATE F_AuditAttribution  → runs/A-L2/mutated_F_AuditAttribution.als
