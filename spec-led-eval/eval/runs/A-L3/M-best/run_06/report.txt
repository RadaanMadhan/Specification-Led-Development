  Mutation tests  (assertion-strength validation)
==============================================================================

  Strategy: replace each named fact's body with `{}` (no constraint),
  then re-run Alloy. Each listed assertion should now FAIL on the
  mutated model. If it still PASSes, the assertion is vacuous and
  must be strengthened.

  - MUTATE F_NoSelfAssignment  → runs/A-L3/mutated_F_NoSelfAssignment.als
    rationale: Clearing this fact lets Alloy assign an application's applicant as its own assigned officer — the conflict-of-interest violation FR-011 forbids. No other fact enforces applicant != assignedOfficer at the application level.
    expected to FAIL: NoSelfMutation, FR_011_NoSelfAssignment
      - NoSelfMutation: FAIL (expected)
      - FR_011_NoSelfAssignment: FAIL (expected)

  - MUTATE F_AuditPairing  → runs/A-L3/mutated_F_AuditPairing.als
    rationale: Clearing this fact lets a successful state-changing operation exist with no audit entry and lets orphan audit entries exist that no operation produced — exactly the audit-completeness and append-only violations.
    expected to FAIL: AuditCompleteness, AppendOnly, FR_017_AuditPairedWithTransition, FR_018_AuditAppendOnly, FR_019_NoAuditDeletion
      - AuditCompleteness: FAIL (expected)
      - AppendOnly: FAIL (expected)
      - FR_017_AuditPairedWithTransition: FAIL (expected)
      - FR_018_AuditAppendOnly: FAIL (expected)
      - FR_019_NoAuditDeletion: FAIL (expected)

  - MUTATE F_OneInFlightPerApplicant  → runs/A-L3/mutated_F_OneInFlightPerApplicant.als
    rationale: Clearing this fact lets one applicant hold two simultaneous in-flight applications, violating the FR-008 partial-unique-index rule from data-model.md.
    expected to FAIL: FR_008_OneInFlight
      - FR_008_OneInFlight: FAIL (expected)

  - MUTATE F_RoleMultiplicity  → runs/A-L3/mutated_F_RoleMultiplicity.als
    rationale: Clearing this fact allows a user to hold both officer and auditor at once, which FR-002 explicitly forbids; no other fact rules out the combination.
    expected to FAIL: FR_002_RoleMultiplicity
      - FR_002_RoleMultiplicity: FAIL (expected)

  - MUTATE F_NoInfoLeakage  → runs/A-L3/mutated_F_NoInfoLeakage.als
    rationale: Clearing this fact lets an unauthorised authenticated GET return a non-NotFound response (e.g., Forbidden), leaking that the application exists — exactly the FR-020/021/022 byte-equivalence breach.
    expected to FAIL: NoInformationLeakage, FR_020_ByteEquivalentUnauthorisedRead
      - NoInformationLeakage: FAIL (expected)
      - FR_020_ByteEquivalentUnauthorisedRead: FAIL (expected)

  - MUTATE F_OwnershipBasedAccess  → runs/A-L3/mutated_F_OwnershipBasedAccess.als
    rationale: Clearing this fact lets an applicant-only caller successfully GET an application they don't own and aren't an officer for, violating ownership-conditional read access (FR-003).
    expected to FAIL: OwnershipBasedAccess, FR_003_ApplicantScope
      - OwnershipBasedAccess: FAIL (expected)
      - FR_003_ApplicantScope: FAIL (expected)
