  - MUTATE F_AppendOnlyAuditEntries  → runs/B-L3/mutated_F_AppendOnlyAuditEntries.als
    rationale: Removing the uniqueness constraint on AuditEntries allows the model to produce two identical AuditEntry atoms (same task, actor, role, operation) — exactly what the AppendOnly and FR_017 assertions are checking against. The injection forces two structurally identical entries to co-exist, which both predicates reject.
    expected to FAIL: AppendOnly, FR_017_AuditImmutableAndPersisted
      - AppendOnly: FAIL (expected)
      - FR_017_AuditImmutableAndPersisted: FAIL (expected)

  - MUTATE F_OnlyOwnerCanShareOrUnshare  → runs/B-L3/mutated_F_OnlyOwnerCanShareOrUnshare.als
    rationale: Clearing this fact removes the rule that only the owner may perform Shared/Unshared mutations. The injection forces a Mutation of kind Shared whose actor is NOT the task owner, which both FR_010_OwnerOnlyShareControl and OwnershipBasedAccess are designed to catch.
    expected to FAIL: FR_010_OwnerOnlyShareControl, OwnershipBasedAccess
      - FR_010_OwnerOnlyShareControl: FAIL (expected)
      - OwnershipBasedAccess: FAIL (expected)

  - MUTATE F_ShareeInSameTeam  → runs/B-L3/mutated_F_ShareeInSameTeam.als
    rationale: Removing this fact lets the model put a User from a different Team into a Task's taskSharedWith set. The injection forces exactly that, which all three cross-team isolation assertions catch.
    expected to FAIL: FR_012_CrossTeamSharingForbidden, FR_006_CrossTeamIsolationAbsolute, FR_014_CrossTeamIsolation
      - FR_012_CrossTeamSharingForbidden: FAIL (expected)
      - FR_006_CrossTeamIsolationAbsolute: FAIL (expected)
      - FR_014_CrossTeamIsolation: FAIL (expected)

  - MUTATE F_AuditEntryHasOneMutation  → runs/B-L3/mutated_F_AuditEntryHasOneMutation.als
    rationale: Clearing this fact removes the requirement that every AuditEntry is linked to exactly one Mutation (i.e., orphan audit entries become possible). The injection forces an AuditEntry that no Mutation references via mutEntry, which both completeness assertions detect as a violation of the bijection.
    expected to FAIL: AuditCompleteness, FR_015_AuditCompletenessAndAtomicity
      - AuditCompleteness: FAIL (expected)
      - FR_015_AuditCompletenessAndAtomicity: FAIL (expected)

  - MUTATE F_AuditActorRoleMatchesUserRole  → runs/B-L3/mutated_F_AuditActorRoleMatchesUserRole.als
    rationale: Removing the snapshot rule allows an AuditEntry to record an actor_role that differs from the actor's actual role — misattribution. The injection forces such a mismatch, which AttributionCorrectness and FR_016_AttributionSnapshot both catch.
