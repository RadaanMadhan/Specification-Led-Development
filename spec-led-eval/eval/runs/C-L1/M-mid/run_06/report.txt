  Mutation tests  (assertion-strength validation)
==============================================================================

  Strategy: replace each named fact's body with `{}` (no constraint),
  then re-run Alloy. Each listed assertion should now FAIL on the
  mutated model. If it still PASSes, the assertion is vacuous and
  must be strengthened.

  - MUTATE F_AppendOnlyAuditEntries  → runs/C-L1/mutated_F_AppendOnlyAuditEntries.als
    rationale: Removing this fact allows two distinct AccessRequests to reference the same AuditEntry, which models an audit record being 'overwritten' rather than a fresh entry appended. The injection forces exactly that sharing.
    expected to FAIL: AppendOnly, FR_010_AuditAppendOnly
      - AppendOnly: FAIL (expected)
      - FR_010_AuditAppendOnly: FAIL (expected)

  - MUTATE F_PermissionMatrix  → runs/C-L1/mutated_F_PermissionMatrix.als
    rationale: Clearing the permission matrix removes the closed-world constraint. The injection adds AuditOfficer -> PostRecordsLookup to the allowed set, which directly violates LeastPrivilege (AuditOfficer is not a clinical role and must not access patient records) and PermissionCompleteness (that cell must be denied).
    expected to FAIL: LeastPrivilege, PermissionCompleteness
      - LeastPrivilege: FAIL (expected)
      - PermissionCompleteness: FAIL (expected)

  - MUTATE F_CareTeamMembershipGating  → runs/C-L1/mutated_F_CareTeamMembershipGating.als
    rationale: Clearing this fact removes the rule that Permitted requires an active care-team membership. The injection forces a Permitted outcome on PostRecordsLookup for a caller who has no active membership, which is exactly the SC-010 violation.
    expected to FAIL: OwnershipBasedAccess, FR_006_CareTeamGating
      - OwnershipBasedAccess: FAIL (expected)
      - FR_006_CareTeamGating: FAIL (expected)

  - MUTATE F_UnauthenticatedProducesNoAuditEntry  → runs/C-L1/mutated_F_UnauthenticatedProducesNoAuditEntry.als
    rationale: Removing this fact allows an unauthenticated request to carry an AuditEntry, violating the rule that the auth boundary is crossed before any patient identifier is dereferenced and before any audit record is written.
    expected to FAIL: AuthRequiredEverywhere, FR_001_AuthRequired
      - AuthRequiredEverywhere: FAIL (expected)
      - FR_001_AuthRequired: FAIL (expected)

  - MUTATE F_ByteEquivalentRefusal  → runs/C-L1/mutated_F_ByteEquivalentRefusal.als
    rationale: Removing this fact allows a Denied request to return RecordContent instead of NotFoundResponse, leaking to the caller that the patient exists but access was refused — the exact information-leakage FR-007 forbids.
    expected to FAIL: NoInformationLeakage, FR_007_ByteEquivalentRefusal
      - NoInformationLeakage: FAIL (expected)
      - FR_007_ByteEquivalentRefusal: FAIL (expected)

  - MUTATE F_IGEndpointHiddenFromClinicalRoles  → runs/C-L1/mutated_F_IGEndpointHiddenFromClinicalRoles.als
    rationale: Removing this fact allows a Doctor-role caller to obtain a non-NotFoundResponse from PostAuditSearch, leaking the existence of the IG audit endpoint to clinical users in violation of SC-011.
    expected to FAIL: NoInformationLeakage, FR_011_IGEndpointHiddenFromClinicians
      - NoInformationLeakage: PASS (vacuous?)
      - FR_011_IGEndpointHiddenFromClinicians: PASS (vacuous?)
