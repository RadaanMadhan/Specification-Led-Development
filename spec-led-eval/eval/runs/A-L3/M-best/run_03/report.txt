  Strategy: replace each named fact's body with `{}` (no constraint),
  then re-run Alloy. Each listed assertion should now FAIL on the
  mutated model. If it still PASSes, the assertion is vacuous and
  must be strengthened.

  - MUTATE F_AppendOnlyAuditEntries  → runs/A-L3/mutated_F_AppendOnlyAuditEntries.als
    rationale: removing this fact lets Alloy materialise two distinct audit entries recording the same (application, prev->new) transition — i.e., a history rewrite, which the append-only invariant exists to forbid.
    expected to FAIL: AppendOnly, FR_018_AuditAppendOnly
      - AppendOnly: FAIL (expected)
      - FR_018_AuditAppendOnly: FAIL (expected)

  - MUTATE F_NoSelfAssignment  → runs/A-L3/mutated_F_NoSelfAssignment.als
    rationale: removing the schema-level no-self-assignment lets Alloy assign an application's officer to be the same user as the applicant, which FR-011 and the CHECK constraint forbid.
    expected to FAIL: NoSelfMutation, FR_011_NoSelfAssignment
      - NoSelfMutation: FAIL (expected)
      - FR_011_NoSelfAssignment: FAIL (expected)

  - MUTATE F_StatusReflectsAudit  → runs/A-L3/mutated_F_StatusReflectsAudit.als
    rationale: removing this fact lets Alloy invent an application whose current status has no witnessing audit entry — exactly the 'observable state change without audit' case that SC-008 forbids.
    expected to FAIL: AuditCompleteness
      - AuditCompleteness: FAIL (expected)

  - MUTATE F_LeastPrivilege  → runs/A-L3/mutated_F_LeastPrivilege.als
    rationale: removing the enforcement fact while keeping the matrix definition lets Alloy materialise an operation whose caller's role set has no allowed cell for the operation's kind — the canonical least-privilege violation.
    expected to FAIL: LeastPrivilege
      - LeastPrivilege: FAIL (expected)

  - MUTATE F_GetApplicationOutcome  → runs/A-L3/mutated_F_GetApplicationOutcome.als
    rationale: removing the outcome-binding fact lets Alloy mark an unauthorised GET as OkSuccess — leaking the existence of an application to a caller who is neither the applicant, the assigned officer, nor an auditor.
    expected to FAIL: NoInformationLeakage, FR_020_ByteEquivalentNoLeak, OwnershipBasedAccess
      - NoInformationLeakage: FAIL (expected)
      - FR_020_ByteEquivalentNoLeak: FAIL (expected)
      - OwnershipBasedAccess: FAIL (expected)

  - MUTATE F_OneInFlightPerApplicant  → runs/A-L3/mutated_F_OneInFlightPerApplicant.als
    rationale: removing the in-flight uniqueness fact lets Alloy create two simultaneous in-flight applications for the same applicant, which the partial-unique index in data-model.md structurally forbids.
    expected to FAIL: FR_008_OneInFlight
      - FR_008_OneInFlight: FAIL (expected)
