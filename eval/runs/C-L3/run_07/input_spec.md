# Feature: Clinical Record Access

## Functional Requirements
- **FR-001**: Authorised clinicians can retrieve structured patient records via a secure API. Records include: patient demographics, medical history, active prescriptions, allergy list, and diagnostic results. The API must respond within 300ms at p95 for a single patient record retrieval and within 800ms at p99 for a full record bundle. Data returned must reflect the state committed within the last 5 seconds (eventual consistency window).
- **FR-002**: Access control must implement the principle of least privilege using attribute-based access control (ABAC). A clinician may only access records for patients under their active care. Emergency override access is permitted but must trigger an immediate alert to the data governance team within 30 seconds. Authentication must use NHS-compliant smart card or MFA. Unauthorised access attempts must be blocked and alerted within 10 seconds. Authentication coverage must be 100% with zero unauthenticated paths.
- **FR-003**: The system must achieve 99.95% uptime measured monthly to satisfy NHS Digital Service Standard requirements. RTO is 10 minutes and RPO is 30 seconds. The system must support a minimum of 200 concurrent clinician sessions without latency degradation. Disaster recovery drills must be conducted quarterly and results documented.
- **FR-004**: All record access events must be written to an immutable, tamper-evident audit log within 10 seconds of the access occurring. Log entries must include: event_id, clinician_id, patient_id, record_type, access_reason, timestamp_utc, ip_address, and session_id. Logs must be retained for a minimum of 8 years in accordance with NHS Records Management Code of Practice. Log completeness must be >= 99.99% with automated alerting on any gap.
