  Strategy: replace each named fact's body with `{}` (no constraint),
  then re-run Alloy. Each listed assertion should now FAIL on the
  mutated model. If it still PASSes, the assertion is vacuous and
  must be strengthened.

  - MUTATE F_OwnerOrAdminForMutation  → runs/B-L2/mutated_F_OwnerOrAdminForMutation.als
    rationale: Clearing this fact lets a Member who is not the task's owner succeed at PATCH/DELETE; the injected fact constructs exactly such a Success op (non-owner, role=Member), which the OwnershipBasedAccess predicate is supposed to forbid.
    expected to FAIL: OwnershipBasedAccess, FR_008_OwnerCanMutate, FR_009_NonOwnerMemberDenied
      - OwnershipBasedAccess: FAIL (expected)
      - FR_008_OwnerCanMutate: FAIL (expected)
      - FR_009_NonOwnerMemberDenied: FAIL (expected)

  - MUTATE F_CrossTeamIsolation  → runs/B-L2/mutated_F_CrossTeamIsolation.als
    rationale: Removing this fact allows a Success operation to act on a task whose team differs from the caller's X-Team-Id. The injection forces such an instance — a clear cross-team leak that NoInformationLeakage must catch.
    expected to FAIL: NoInformationLeakage, FR_011_CrossTeamIsolation, FR_014_ByteEquivalentNotFound
      - NoInformationLeakage: FAIL (expected)
      - FR_011_CrossTeamIsolation: FAIL (expected)
      - FR_014_ByteEquivalentNotFound: FAIL (expected)

  - MUTATE F_PermissionMatrix  → runs/B-L2/mutated_F_PermissionMatrix.als
    rationale: Clearing the matrix definition lets PermMatrix.Allowed be anything. The injection collapses it to empty, so PermissionCompleteness (every Role x OperationKind cell present) fails.
    expected to FAIL: PermissionCompleteness
      - PermissionCompleteness: PASS (vacuous?)

  - MUTATE F_AuditEntryForStateChange  → runs/B-L2/mutated_F_AuditEntryForStateChange.als
    rationale: Without this fact, a successful PATCH need not produce an audit entry. The injection forces a PATCH-Success op with writesAudit empty, which AuditCompleteness must reject.
    expected to FAIL: AuditCompleteness, FR_015_AuditPerEdit
      - AuditCompleteness: FAIL (expected)
      - FR_015_AuditPerEdit: FAIL (expected)

  - MUTATE F_AuditAppendOnlyKind  → runs/B-L2/mutated_F_AuditAppendOnlyKind.als
    rationale: Removing this fact lets an audit entry's kind diverge from its producing operation's kind — e.g., a PostTasks op producing a DeletedKind entry, which is impossible under an append-only invariant where the kind is fixed at insert time.
    expected to FAIL: AppendOnly, FR_016_AuditAppendOnly
      - AppendOnly: FAIL (expected)
      - FR_016_AuditAppendOnly: FAIL (expected)

  - MUTATE F_AuditAttribution  → runs/B-L2/mutated_F_AuditAttribution.als

      - FR_015_AuditPerEdit: FAIL (expected)
