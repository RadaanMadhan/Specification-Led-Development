  Strategy: replace each named fact's body with `{}` (no constraint),
  then re-run Alloy. Each listed assertion should now FAIL on the
  mutated model. If it still PASSes, the assertion is vacuous and
  must be strengthened.

  - MUTATE F_PermissionMatrix  → runs/B-L3/mutated_F_PermissionMatrix.als
    rationale: Clearing the matrix definition lets Alloy invent any (Relationship, OperationKind) cell. The injected fact forces a Sharee-can-delete cell, which directly violates the least-privilege and Q3=B sharee-cannot-delete invariants.
    expected to FAIL: LeastPrivilege, FR_010_OwnerOnlyShares, FR_011_ShareeViewEditNoDelete
      - LeastPrivilege: FAIL (expected)
      - FR_010_OwnerOnlyShares: FAIL (expected)
      - FR_011_ShareeViewEditNoDelete: FAIL (expected)

  - MUTATE F_OneCreatedPerTask  → runs/B-L3/mutated_F_OneCreatedPerTask.als
    rationale: Removing the 'exactly one created entry per task' fact lets Alloy build a task with no created audit entry, which is exactly what AuditCompleteness must reject.
    expected to FAIL: AuditCompleteness, FR_015_OneAuditPerCreate
      - AuditCompleteness: FAIL (expected)
      - FR_015_OneAuditPerCreate: FAIL (expected)

  - MUTATE F_AtMostOneDeletedPerTask  → runs/B-L3/mutated_F_AtMostOneDeletedPerTask.als
    rationale: Append-only forbids two deletion entries for the same task. Clearing the fact and forcing two such entries directly exhibits the mutation/replay scenario the assertion must catch.
    expected to FAIL: AppendOnly, FR_017_AuditAppendOnly
      - AppendOnly: FAIL (expected)
      - FR_017_AuditAppendOnly: FAIL (expected)

  - MUTATE F_AuditActorInTaskTeam  → runs/B-L3/mutated_F_AuditActorInTaskTeam.als
    rationale: If the actor-in-team constraint is removed, a user in team T could be recorded as having mutated a task in team U — exactly the cross-team leak that FR-014's byte-equivalent 404 is built to prevent.
    expected to FAIL: NoInformationLeakage, FR_006_CrossTeamIsolation, FR_014_ByteEquivIsolation
      - NoInformationLeakage: FAIL (expected)
      - FR_006_CrossTeamIsolation: FAIL (expected)
      - FR_014_ByteEquivIsolation: FAIL (expected)

  - MUTATE F_AuditAttribution  → runs/B-L3/mutated_F_AuditAttribution.als
    rationale: Without the snapshot-matches-actor constraint, Alloy can fabricate an audit entry whose recorded role contradicts the actor's actual role, exhibiting misattribution.
    expected to FAIL: AttributionCorrectness, FR_016_AuditFieldsPresent
      - AttributionCorrectness: FAIL (expected)
