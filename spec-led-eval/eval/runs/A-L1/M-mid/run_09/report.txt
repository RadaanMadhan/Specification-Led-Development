  Strategy: replace each named fact's body with `{}` (no constraint),
  then re-run Alloy. Each listed assertion should now FAIL on the

  must be strengthened.

  - MUTATE F_OnePendingPerCustomer  → runs/A-L1/mutated_F_OnePendingPerCustomer.als
    rationale: Removing this fact allows two LoanApplications with PendingReview status to share the same customer, directly violating FR-005 and the uniqueness invariant the assertion checks.
    expected to FAIL: FR_005_OnePendingPerCustomer, ConcurrencySafety
      - FR_005_OnePendingPerCustomer: FAIL (expected)
      - ConcurrencySafety: PASS (vacuous?)

  - MUTATE F_AtMostOneDecisionPerApp  → runs/A-L1/mutated_F_AtMostOneDecisionPerApp.als
    rationale: Removing this fact permits two distinct Decision rows referencing the same application, modelling a failed concurrency guard (FR-012, SC-005). The ConcurrencySafety and FR_011 assertions should then find a counterexample.
    expected to FAIL: ConcurrencySafety, FR_011_NoReDecisionOnDecidedApp
      - ConcurrencySafety: PASS (vacuous?)
      - FR_011_NoReDecisionOnDecidedApp: PASS (vacuous?)

  - MUTATE F_AppendOnlyAuditEntries  → runs/A-L1/mutated_F_AppendOnlyAuditEntries.als
    rationale: Removing the append-only fact allows an ApplicationEvent with eventType EvtApproved to exist on an application that is still in PendingReview, simulating a forged or out-of-order audit entry — exactly what the AppendOnly assertion is meant to catch.
    expected to FAIL: AppendOnly, FR_016_AuditTrailCompleteness, AuditCompleteness
      - AppendOnly: PASS (vacuous?)
      - FR_016_AuditTrailCompleteness: PASS (vacuous?)
      - AuditCompleteness: PASS (vacuous?)

  - MUTATE F_NoInfoLeakage  → runs/A-L1/mutated_F_NoInfoLeakage.als
    rationale: Removing this fact allows an Operation where a customer accesses another customer's application and receives Forbidden instead of NotFound, leaking existence information in violation of FR-013 and SC-004.
    expected to FAIL: NoInformationLeakage, FR_013_CustomerSeesOnlyOwnApps
      - NoInformationLeakage: FAIL (expected)
      - FR_013_CustomerSeesOnlyOwnApps: FAIL (expected)

  - MUTATE F_DeciderHasBankStaffRole  → runs/A-L1/mutated_F_DeciderHasBankStaffRole.als
    rationale: Removing this fact allows a Decision to be recorded by a user with CustomerRole as decidedBy, breaking the bank-staff-only restriction from FR-015. LeastPrivilege and FR_015 assertions should then fail.
    expected to FAIL: FR_015_OnlyStaffCanDecide, LeastPrivilege
      - FR_015_OnlyStaffCanDecide: FAIL (expected)
      - LeastPrivilege: PASS (vacuous?)
