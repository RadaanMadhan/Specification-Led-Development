  Strategy: replace each named fact's body with `{}` (no constraint),

  - MUTATE F_CareTeamGating  → runs/C-L2/mutated_F_CareTeamGating.als
    rationale: Clearing this fact removes the constraint that a Permitted clinical-endpoint outcome requires an active care-team membership. The injected violation forces a Permitted RecordsLookup operation with no matching ActiveMembership, which both OwnershipBasedAccess and FR_004_CareTeamGating check for.
    expected to FAIL: OwnershipBasedAccess, FR_004_CareTeamGating
      - OwnershipBasedAccess: PASS (vacuous?)
      - FR_004_CareTeamGating: PASS (vacuous?)

  - MUTATE F_AuditInjective  → runs/C-L2/mutated_F_AuditInjective.als
    rationale: Clearing this fact allows two distinct Operations to share a single AuditEntry atom, simulating an audit-log entry being 'overwritten' or 'reused'. The injection forces exactly this sharing, which AppendOnly and FR_014_AuditImmutable directly check.
    expected to FAIL: AppendOnly, FR_014_AuditImmutable, AuditCompleteness
      - AppendOnly: PASS (vacuous?)
      - FR_014_AuditImmutable: PASS (vacuous?)
      - AuditCompleteness: PASS (vacuous?)

  - MUTATE F_NoteAuthorIsClinical  → runs/C-L2/mutated_F_NoteAuthorIsClinical.als
    rationale: Clearing this fact removes the structural constraint that clinical notes must be authored by clinical-role users. The injection forces a ClinicalNote authored by a HospitalAdministrator, violating both FR_005_AdminContentBlindness and FR_010_NoteAuthorClinical.
    expected to FAIL: FR_005_AdminContentBlindness, FR_010_NoteAuthorClinical
      - FR_005_AdminContentBlindness: PASS (vacuous?)
      - FR_010_NoteAuthorClinical: PASS (vacuous?)

  - MUTATE F_AuditNoteIdRule  → runs/C-L2/mutated_F_AuditNoteIdRule.als
    rationale: Clearing this fact removes the biconditional that auditNote is set iff the access type is AddNote and the outcome is Permitted. The injection forces an AuditEntry with accessType=Read to carry a non-null auditNote, directly violating FR_013_AuditNoteIdConsistency.
    expected to FAIL: FR_013_AuditNoteIdConsistency
      - FR_013_AuditNoteIdConsistency: FAIL (expected)

  - MUTATE F_AuditSearchAdminOnly  → runs/C-L2/mutated_F_AuditSearchAdminOnly.als
    rationale: Clearing this fact allows a non-administrator (e.g., a Doctor) to appear as the caller of an AuditSearch Operation. The injection forces this, violating both FR_017_AuditSearchAdminOnly and NoInformationLeakage (which requires that clinical callers never reach the AuditSearch handler).
    expected to FAIL: FR_017_AuditSearchAdminOnly, NoInformationLeakage
      - FR_017_AuditSearchAdminOnly: FAIL (expected)
      - NoInformationLeakage: FAIL (expected)

  - MUTATE F_AuditAttribution  → runs/C-L2/mutated_F_AuditAttribution.als
    rationale: Clearing this fact allows an AuditEntry's auditUser to differ from the Operation's opCaller, simulating misattribution. The injection forces an operation whose audit entry records a different user, violating both AttributionCorrectness and FR_013_AttributionIntegrity.
    expected to FAIL: AttributionCorrectness, FR_013_AttributionIntegrity
      - AttributionCorrectness: FAIL (expected)
      - FR_013_AttributionIntegrity: FAIL (expected)
