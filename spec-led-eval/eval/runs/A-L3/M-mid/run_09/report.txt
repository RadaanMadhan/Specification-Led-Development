    rationale: Removing F_AppendOnlyAuditEntries allows the model to produce two AuditEntries for the same application that record the same (prevStatus, newStatus) — exactly an in-place update of a prior entry. The injection forces this violated instance to exist so AppendOnly and FR_018_AuditImmutable both find counterexamples.
    expected to FAIL: AppendOnly, FR_018_AuditImmutable
      - AppendOnly: FAIL (expected)
      - FR_018_AuditImmutable: FAIL (expected)

  - MUTATE F_NoSelfApproval  → runs/A-L3/mutated_F_NoSelfApproval.als
    rationale: Removing F_NoSelfApproval allows an officer to decide their own application. The injection forces an AuditEntry whose actor is the same User as the application's applicant and has a non-null prevStatus, directly violating the no-self-approval invariant.
    expected to FAIL: NoSelfMutation, FR_013_NoSelfApproval, OwnershipBasedAccess
      - NoSelfMutation: PASS (vacuous?)
      - FR_013_NoSelfApproval: PASS (vacuous?)
      - OwnershipBasedAccess: PASS (vacuous?)

  - MUTATE F_RoleMultiplicity  → runs/A-L3/mutated_F_RoleMultiplicity.als
