  - MUTATE F_ClosedTaskEditRule  → runs/B-L1/mutated_F_ClosedTaskEditRule.als
    rationale: Removing F_ClosedTaskEditRule lets the model produce an EditOperation on a Done task that Succeeded without supplying a non-Done new status, directly violating the closed-task invariant. The injected fact forces exactly that shape.
    expected to FAIL: ValidationBeforeMutation, FR_011_ClosedTaskEditRule
      - ValidationBeforeMutation: PASS (vacuous?)
      - FR_011_ClosedTaskEditRule: PASS (vacuous?)

  - MUTATE F_DeletionLogComplete  → runs/B-L1/mutated_F_DeletionLogComplete.als

    expected to FAIL: AuditCompleteness, FR_018_DeletionLogged
      - AuditCompleteness: PASS (vacuous?)

    expected to FAIL: PermissionCompleteness, FR_004_FlatPermissions
      - PermissionCompleteness: PASS (vacuous?)
      - FR_004_FlatPermissions: PASS (vacuous?)

  - MUTATE F_AssigneeMustBeMember  → runs/B-L1/mutated_F_AssigneeMustBeMember.als
    rationale: Removing F_AssigneeMustBeMember permits a Task to have an assignee that is not in Member, or to have more than one assignee (since the lone cardinality of the sig field still holds but the fact that enforces membership is gone).
