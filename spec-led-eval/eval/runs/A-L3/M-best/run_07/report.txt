  Mutation tests  (assertion-strength validation)
==============================================================================

  Strategy: replace each named fact's body with `{}` (no constraint),
  then re-run Alloy. Each listed assertion should now FAIL on the
  mutated model. If it still PASSes, the assertion is vacuous and
  must be strengthened.

  - MUTATE F_AuditAppendOnly  → runs/A-L3/mutated_F_AuditAppendOnly.als
    rationale: Removing this fact lets the model construct two distinct audit entries describing the same (application, prev_status, new_status) transition, which is exactly the append-only/duplicate violation the assertion forbids.
    expected to FAIL: AppendOnly, FR_018_AuditAppendOnly
      - AppendOnly: FAIL (expected)
      - FR_018_AuditAppendOnly: FAIL (expected)

  - MUTATE F_NoSelfAssignment  → runs/A-L3/mutated_F_NoSelfAssignment.als
    rationale: Removing this fact allows the auto-assignment to produce an application whose assigned officer is the same user as the applicant, violating FR-011.
    expected to FAIL: NoSelfMutation, FR_011_NoSelfAssignment
      - NoSelfMutation: FAIL (expected)
      - FR_011_NoSelfAssignment: FAIL (expected)

  - MUTATE F_PatchRequiresAssignedOfficerNotApplicant  → runs/A-L3/mutated_F_PatchRequiresAssignedOfficerNotApplicant.als
    rationale: Removing this fact allows a successful PATCH where the caller is the application's applicant (self-decision) or not its assigned officer — both forbidden by FR-012/FR-013/FR-024.
    expected to FAIL: NoSelfMutation, FR_013_NoSelfDecision, FR_012_OnlyAssignedOfficerCanPatch, FR_024_ApplicantCannotModify
      - NoSelfMutation: FAIL (expected)
      - FR_013_NoSelfDecision: FAIL (expected)
      - FR_012_OnlyAssignedOfficerCanPatch: FAIL (expected)
      - FR_024_ApplicantCannotModify: FAIL (expected)

  - MUTATE F_NotFoundForUnauthorizedReads  → runs/A-L3/mutated_F_NotFoundForUnauthorizedReads.als
    rationale: Removing this fact lets an unauthorized GET on an existing application return Ok instead of the byte-equivalent NotFound, leaking the application's existence to an outsider.
    expected to FAIL: NoInformationLeakage, FR_020_NotFoundForUnauthorizedReads, FR_021_NoCrossApplicantLeak
      - NoInformationLeakage: FAIL (expected)
      - FR_020_NotFoundForUnauthorizedReads: FAIL (expected)
      - FR_021_NoCrossApplicantLeak: FAIL (expected)

  - MUTATE F_AuthBeforeBusinessLogic  → runs/A-L3/mutated_F_AuthBeforeBusinessLogic.als
    rationale: Removing this fact lets an unauthenticated request succeed with response Ok, bypassing the OAuth bearer requirement that FR-001 makes mandatory before any business logic.
    expected to FAIL: AuthRequiredEverywhere, FR_001_AuthRequired
      - AuthRequiredEverywhere: FAIL (expected)
      - FR_001_AuthRequired: FAIL (expected)

  - MUTATE F_AuditOnlyOnSuccessfulStateChange  → runs/A-L3/mutated_F_AuditOnlyOnSuccessfulStateChange.als
    rationale: Removing this fact lets the model produce an audit entry for a failed (non-Ok) operation, violating the atomic-commit guarantee of FR-017 and the validation-before-mutation pattern.
    expected to FAIL: ValidationBeforeMutation, FR_017_AuditAtomicWithTransition, AuditCompleteness
      - ValidationBeforeMutation: FAIL (expected)
      - FR_017_AuditAtomicWithTransition: FAIL (expected)
      - AuditCompleteness: FAIL (expected)
