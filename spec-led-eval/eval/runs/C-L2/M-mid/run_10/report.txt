  Strategy: replace each named fact's body with `{}` (no constraint),
  then re-run Alloy. Each listed assertion should now FAIL on the
  mutated model. If it still PASSes, the assertion is vacuous and
  must be strengthened.

  - MUTATE F_AppendOnlyNotes  → runs/C-L2/mutated_F_AppendOnlyNotes.als
    rationale: Removing this fact allows ClinicalNote atoms to exist without any corresponding permitted AddNote operation, breaking the append-only invariant. The injection forces a note that has no creating operation, exactly the state the AppendOnly predicate forbids.
    expected to FAIL: AppendOnly, FR_011_NotesAppendOnly, FR_009_ValidationBeforeMutation
      - AppendOnly: FAIL (expected)
      - FR_011_NotesAppendOnly: FAIL (expected)
      - FR_009_ValidationBeforeMutation: FAIL (expected)

  - MUTATE F_AuditOneToOneWithOperation  → runs/C-L2/mutated_F_AuditOneToOneWithOperation.als
    rationale: Removing this fact allows an Operation to share its AuditEntry with another Operation, and allows AuditEntry atoms to exist with no owning Operation. The injection creates an orphan AuditEntry, violating the one-to-one correspondence the AuditCompleteness assertion requires.
    expected to FAIL: AuditCompleteness, FR_012_AlwaysOnAudit, FR_014_AuditEntriesImmutable
      - AuditCompleteness: FAIL (expected)
      - FR_012_AlwaysOnAudit: FAIL (expected)
      - FR_014_AuditEntriesImmutable: FAIL (expected)

  - MUTATE F_RoleOperationPermission  → runs/C-L2/mutated_F_RoleOperationPermission.als
    rationale: Removing this fact lifts the constraint that every operation's caller holds an allowed role for that operation kind. The injection forces a HospitalAdministrator to perform a permitted RecordLookup, which the LeastPrivilege assertion directly forbids.
    expected to FAIL: LeastPrivilege, PermissionCompleteness, FR_017_ListAuditAdminOnly, FR_005_AdminContentBlindness
      - LeastPrivilege: FAIL (expected)
      - PermissionCompleteness: PASS (vacuous?)
      - FR_017_ListAuditAdminOnly: FAIL (expected)
      - FR_005_AdminContentBlindness: FAIL (expected)

  - MUTATE F_CareTeamGatingForClinicalOps  → runs/C-L2/mutated_F_CareTeamGatingForClinicalOps.als
    rationale: Removing this fact allows a clinical operation to be permitted even when no CareTeamMembership row links the caller to the patient. The injection forces a permitted RecordLookup where no membership exists, which is exactly the ownership-based-access violation.
    expected to FAIL: OwnershipBasedAccess, FR_004_CareTeamGating
      - OwnershipBasedAccess: FAIL (expected)
      - FR_004_CareTeamGating: FAIL (expected)

  - MUTATE F_ClinicalNoteAuthorMustBeClinicalRole  → runs/C-L2/mutated_F_ClinicalNoteAuthorMustBeClinicalRole.als
    rationale: Removing this fact allows a ClinicalNote to be authored by a HospitalAdministrator. The injection forces such a note to exist, violating the structural CHECK that no administrator role may appear as an author.
    expected to FAIL: FR_010_NoteAuthorIsClinicalRole, FR_005_AdminContentBlindness
      - FR_010_NoteAuthorIsClinicalRole: PASS (vacuous?)
      - FR_005_AdminContentBlindness: PASS (vacuous?)

  - MUTATE F_NoteRefAuditConstraint  → runs/C-L2/mutated_F_NoteRefAuditConstraint.als
