# Data Model: HIPAA Hospital Clinical Record Access

**Branch**: `013-hipaa-clinical-records` | **Date**: 2026-05-17

All entities are persisted in SQLite (`sqlite3` stdlib) in WAL mode. All identifiers are UUID4 strings unless otherwise noted. All timestamps are UTC ISO 8601 with millisecond precision and `Z` suffix. Dates are date-only `YYYY-MM-DD`. IP addresses are stored verbatim as text strings.

## Enums

### Role

```python
class Role(StrEnum):
    CLINICIAN = "clinician"
    PATIENT = "patient"
    COMPLIANCE_OFFICER = "compliance_officer"
```

A user holds exactly one role at a time. Read from the host product's identity context on every request.

### Operation

```python
class Operation(StrEnum):
    READ = "read"      # GET /records/{id}
    APPEND = "append"  # POST /records/{id}/notes
    LIST = "list"      # GET /records/{id}/audit or GET /access-log
```

### Outcome

```python
class Outcome(StrEnum):
    PERMITTED = "permitted"
    DENIED = "denied"
```

(Only two values; "not found" is collapsed into "denied" because the response is byte-equivalent — the audit entry records the actual cause via `authorisation_basis`.)

### AuthorisationBasis

```python
class AuthorisationBasis(StrEnum):
    CARE_TEAM_MEMBER = "care_team_member"
    NOT_CARE_TEAM_MEMBER = "not_care_team_member"
    PATIENT_OWN = "patient_own"
    PATIENT_OTHER = "patient_other"
    COMPLIANCE_ROLE = "compliance_role"
    OUTSIDER = "outsider"
    RECORD_NOT_FOUND = "record_not_found"
```

Recorded on every audit entry. The actual response to the caller is byte-equivalent across all denied bases; the basis is for IG review only.

### NoteType

```python
class NoteType(StrEnum):
    PROGRESS = "progress"
    ASSESSMENT = "assessment"
    PLAN = "plan"
    OBSERVATION = "observation"
    DISCHARGE_SUMMARY = "discharge_summary"
```

The fixed v1 catalogue. New note types would extend this with a clinical-safety case.

### MembershipStatus

```python
class MembershipStatus(StrEnum):
    ACTIVE = "active"
    ENDED = "ended"
```

Only `active` memberships authorise access.

### Relationship (computed, not persisted)

```python
class Relationship(StrEnum):
    OUTSIDER             = "outsider"
    CARE_TEAM_CLINICIAN  = "care_team_clinician"
    PATIENT_OWN_RECORD   = "patient_own_record"
    PATIENT_OTHER_RECORD = "patient_other_record"
    COMPLIANCE_OFFICER   = "compliance_officer"
```

Computed by `permissions.relationship(user, record_id, db)` on every request.

## Entities

### User

| Field                | Type           | Storage                                                                                                  | Notes |
|----------------------|----------------|----------------------------------------------------------------------------------------------------------|-------|
| id                   | str            | TEXT PK                                                                                                  | Opaque identifier from the host product. |
| display_name         | str            | TEXT NOT NULL                                                                                            | Shown in audit-entry rendering. |
| role                 | Role           | TEXT NOT NULL CHECK(role IN ('clinician','patient','compliance_officer'))                                | Exactly one role per user. |
| assigned_record_id   | str \| None    | TEXT NULL                                                                                                | For role `patient`, the one record they are authorised to read. For other roles, MUST be `NULL`. CHECK constraint enforces the pairing. |

**Pairing CHECK**:

```sql
CHECK (
    (role = 'patient' AND assigned_record_id IS NOT NULL)
 OR (role != 'patient' AND assigned_record_id IS NULL)
)
```

No password / credential field; auth is the bearer-token stub.

### Token (auth stub for v1)

| Field      | Type | Storage                              | Notes |
|------------|------|--------------------------------------|-------|
| token      | str  | TEXT PK                              | Opaque bearer-token presented in `Authorization: Bearer <token>`. |
| user_id    | str  | TEXT NOT NULL FK→users.id            | Resolves the token to a user. |
| expires_at | str  | TEXT NOT NULL                        | UTC ISO 8601. Tokens past `expires_at` resolve to no user. |

In real deployment this is replaced by the host product's HIPAA-compliant identity-provider integration.

### Record

| Field         | Type | Storage                  | Notes |
|---------------|------|--------------------------|-------|
| id            | str  | TEXT PK                  | Opaque `record_id`. The handle used in URL paths (FR-020). Generated by the host product's record-management system. |
| patient_name  | str  | TEXT NOT NULL            | Shown in `GET /records/{id}` responses to authorised callers; never in compliance responses (FR-019). |
| date_of_birth | str  | TEXT NOT NULL            | `YYYY-MM-DD`. Shown in `GET /records/{id}` responses to authorised callers; never in compliance responses. |

The `Record` entity is the addressable handle for a patient's medical record. The `record_id` is an opaque internal identifier; the patient demographics it carries are exposed only via authorised reads.

### PatientSummary

A per-record denormalised view including the safety-relevant fields surfaced at the top of every `GET /records/{id}` response (allergies, key warnings, current medications). Read-only in this feature.

| Field                        | Type | Storage                              | Notes |
|------------------------------|------|--------------------------------------|-------|
| record_id                    | str  | TEXT PK FK→records.id                | One row per record. |
| allergies_json               | str  | TEXT NOT NULL DEFAULT '[]'           | JSON array of `{"substance": str, "severity": str, "notes": str}` objects. |
| key_warnings_json            | str  | TEXT NOT NULL DEFAULT '[]'           | JSON array of `{"category": str, "text": str}` objects. |
| current_medications_json     | str  | TEXT NOT NULL DEFAULT '[]'           | JSON array of `{"name": str, "dose": str, "frequency": str}` objects. |

### Encounter

| Field          | Type | Storage                              | Notes |
|----------------|------|--------------------------------------|-------|
| id             | str  | TEXT PK                              | UUID4. |
| record_id      | str  | TEXT NOT NULL FK→records.id          | |
| encounter_date | str  | TEXT NOT NULL                        | `YYYY-MM-DD`. |
| encounter_type | str  | TEXT NOT NULL                        | E.g., `"GP visit"`, `"A&E"`, `"outpatient"`. |
| summary        | str  | TEXT NOT NULL                        | Short summary line. |

**Index**:
- `CREATE INDEX idx_encounters_by_record ON encounters(record_id, encounter_date DESC);`

### CareTeamMembership

The many-to-many relationship between clinicians and records (FR-004). Populated by an out-of-scope feed from the host product's care-team-management system.

| Field              | Type             | Storage                                                                                   | Notes |
|--------------------|------------------|-------------------------------------------------------------------------------------------|-------|
| clinician_id       | str              | TEXT NOT NULL FK→users.id                                                                  | |
| record_id          | str              | TEXT NOT NULL FK→records.id                                                                | |
| episode_of_care_id | str              | TEXT NOT NULL                                                                              | Host product's episode-of-care identifier; opaque here. |
| status             | MembershipStatus | TEXT NOT NULL CHECK(status IN ('active','ended'))                                          | Only `active` rows authorise. |
| start_date         | str              | TEXT NOT NULL                                                                              | UTC ISO 8601. |
| end_date           | str \| None      | TEXT NULL                                                                                  | UTC ISO 8601. NULL while active. |

**Composite PK**: `(clinician_id, record_id, episode_of_care_id)`.

**Index** (the hot-path query for FR-004 / FR-009's 200ms latency target):
- `CREATE INDEX idx_care_team_by_clinician_record ON care_team_memberships(clinician_id, record_id, status);`

### ClinicalNote

Append-only clinical note attached to a record (FR-010, FR-011, FR-012).

| Field                | Type     | Storage                                                                                          | Notes |
|----------------------|----------|--------------------------------------------------------------------------------------------------|-------|
| id                   | str      | TEXT PK                                                                                          | UUID4. Returned to the author on `201 Created`. |
| record_id            | str      | TEXT NOT NULL FK→records.id                                                                      | |
| author_user_id       | str      | TEXT NOT NULL FK→users.id                                                                        | The clinician who added the note. |
| author_display_name  | str      | TEXT NOT NULL                                                                                    | Snapshotted from `users.display_name` at the time of add. |
| author_role          | Role     | TEXT NOT NULL CHECK(author_role = 'clinician')                                                   | Snapshot. Only clinicians may author notes — patient and compliance authorship is structurally impossible. |
| created_at           | str      | TEXT NOT NULL                                                                                    | UTC ISO 8601 with `Z` suffix. |
| note_type            | NoteType | TEXT NOT NULL CHECK(note_type IN ('progress','assessment','plan','observation','discharge_summary')) | |
| body                 | str      | TEXT NOT NULL CHECK(length(body) BETWEEN 1 AND 8000)                                              | Free text; trimmed at submission; 1–8000 chars. |
| encounter_date       | str      | TEXT NOT NULL CHECK(date(encounter_date) <= date(created_at))                                     | Defaults to date portion of `created_at` if not supplied. Future dates rejected. |

**Index**:
- `CREATE INDEX idx_notes_by_record_chrono ON clinical_notes(record_id, created_at, id);`

**Append-only enforcement**:
- No UPDATE/DELETE SQL targets `clinical_notes` in `store.py`. Static probe in `test_invariants.py` verifies; runtime snapshot-hash probe confirms.
- The `author_role = 'clinician'` CHECK forbids `patient` or `compliance_officer` authorship at the database layer (defence-in-depth beyond the API-layer `permissions.is_allowed('append_note', …)` rule).

### AuditEntry

Immutable append-only record of one access event (FR-013, FR-014, FR-015, FR-017).

| Field                        | Type                | Storage                                                                                            | Notes |
|------------------------------|---------------------|----------------------------------------------------------------------------------------------------|-------|
| id                           | int                 | INTEGER PRIMARY KEY AUTOINCREMENT                                                                  | Monotonic; chronological ordering. |
| record_id                    | str \| None         | TEXT NULL                                                                                          | The record accessed. NULL only for `operation = 'list'` events against `GET /access-log` (system-wide; no specific record). |
| accessor_user_id             | str                 | TEXT NOT NULL FK→users.id                                                                          | The caller. |
| accessor_user_display_name   | str                 | TEXT NOT NULL                                                                                       | Snapshot at the time of access. |
| accessor_role                | Role                | TEXT NOT NULL CHECK(accessor_role IN ('clinician','patient','compliance_officer'))                 | Snapshot at the time of access. |
| timestamp                    | str                 | TEXT NOT NULL                                                                                       | UTC ISO 8601 with `Z` suffix. |
| operation                    | Operation           | TEXT NOT NULL CHECK(operation IN ('read','append','list'))                                         | |
| outcome                      | Outcome             | TEXT NOT NULL CHECK(outcome IN ('permitted','denied'))                                             | |
| authorisation_basis          | AuthorisationBasis  | TEXT NOT NULL CHECK(authorisation_basis IN ('care_team_member','not_care_team_member','patient_own','patient_other','compliance_role','outsider','record_not_found')) | Why this outcome — for IG investigation; never exposed in caller responses. |
| originating_ip_address       | str                 | TEXT NOT NULL CHECK(length(originating_ip_address) BETWEEN 7 AND 45)                                | IPv4 dotted-decimal (7–15 chars) or IPv6 (up to 45). Length CHECK is a sanity bound; no strict format validation at the DB. |
| note_id                      | str \| None         | TEXT NULL                                                                                          | Set only when `operation = 'append'` AND `outcome = 'permitted'`. Opaque id; reveals no clinical content. |

**Structural CHECK linking `note_id` to `operation` and `outcome`**:

```sql
CHECK (
    (operation = 'append' AND outcome = 'permitted' AND note_id IS NOT NULL)
 OR (operation = 'append' AND outcome = 'denied' AND note_id IS NULL)
 OR (operation IN ('read','list') AND note_id IS NULL)
)
```

A coding error that fails to insert the note but tries to record an audit entry with `note_id = <bogus>` is rejected at the schema layer.

**Structural CHECK linking `record_id` to `operation`**: `record_id` MAY be NULL only for `operation = 'list'` (the `GET /access-log` case). For `operation IN ('read','append')` it MUST be non-null (it comes from the URL path).

**Indexes**:
- `CREATE INDEX idx_audit_by_record_chrono ON audit_entries(record_id, timestamp, id);` — supports `GET /records/{id}/audit` ordering.
- `CREATE INDEX idx_audit_by_user_chrono ON audit_entries(accessor_user_id, timestamp, id);` — supports `GET /access-log?accessor_user_id=…` filtering.
- `CREATE INDEX idx_audit_chrono ON audit_entries(timestamp, id);` — supports `GET /access-log` no-filter ordering (most-recent first).

**Append-only enforcement**: no UPDATE/DELETE SQL targets `audit_entries` in `store.py`. Static + runtime probes verify.

**7-year retention floor** (FR-017): satisfied by the absence of any DELETE code path. Operational retention scheduling beyond 7 years is out of scope of this feature.

## Entity-relationship diagram

```text
users (1) ─< tokens                                          (auth stub for v1)
   │
   │ (patient ─ 1:1 ─ records via assigned_record_id)
   │
records (1) ──< care_team_memberships >── users (clinicians)   (many-to-many)
   │
   ├── patient_summaries        (1:1; safety-relevant view)
   ├──< encounters              (1:many; chronological)
   ├──< clinical_notes          (1:many; append-only)
   │
   │ (audit_entries NOT FK'd on record_id — audit outlives records,
   │  and records.id may correspond to an unknown record on a denied attempt)
   │
users (1) ─────────────────────< audit_entries
```

The `audit_entries.record_id` column is **not** FK-constrained, deliberately: an attempt against a non-existent `record_id` still produces an audit entry (FR-013), and that entry persists independently of any records-table evolution.

## The HTTP-403 envelope and the audit-entry write — a single 150ms write transaction

The 150ms SQLite connection timeout serves both the 200ms HTTP-403 latency SLA (FR-009) and the 1-second audit-write SLA (FR-016). A successful or refused access flow is:

```text
                                            time budget (200ms 403 case)
    HTTP request arrives                    0ms
        │
        ▼
    Authenticate (token resolution)         ~5ms
        │
        ▼
    Compute relationship (1 indexed SQL)    ~5ms
        │
        ▼ (open BEGIN IMMEDIATE)
    Insert audit entry                      ~5ms
    [+ note insert if permitted append]     ~5ms
        │
        ▼
    COMMIT (with timeout=150ms)             ≤150ms p99
        │
        ▼
    Serialise + send response               ~5ms
                                            ─────
                                            ≤175ms typical, ≤175 + jitter for 99%
```

The 200ms p99 SLA leaves ~25ms of headroom for network jitter and unexpected serialisation cost.

Under contention, COMMIT raises `OperationalError` after 150ms; the handler maps to `503 service_unavailable` with rollback (FR-016). The 1% of requests permitted to take this path (SC-005) is the population that hit the timeout.

## SQL schema (illustrative)

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA temp_store = MEMORY;
PRAGMA mmap_size = 134217728;

CREATE TABLE users (
    id TEXT PRIMARY KEY,
    display_name TEXT NOT NULL,
    role TEXT NOT NULL
        CHECK (role IN ('clinician','patient','compliance_officer')),
    assigned_record_id TEXT,
    CHECK (
        (role = 'patient' AND assigned_record_id IS NOT NULL)
     OR (role != 'patient' AND assigned_record_id IS NULL)
    )
);

CREATE TABLE tokens (
    token TEXT PRIMARY KEY,
    user_id TEXT NOT NULL REFERENCES users(id),
    expires_at TEXT NOT NULL
);

CREATE TABLE records (
    id TEXT PRIMARY KEY,
    patient_name TEXT NOT NULL,
    date_of_birth TEXT NOT NULL
);

CREATE TABLE patient_summaries (
    record_id TEXT PRIMARY KEY REFERENCES records(id),
    allergies_json TEXT NOT NULL DEFAULT '[]',
    key_warnings_json TEXT NOT NULL DEFAULT '[]',
    current_medications_json TEXT NOT NULL DEFAULT '[]'
);

CREATE TABLE encounters (
    id TEXT PRIMARY KEY,
    record_id TEXT NOT NULL REFERENCES records(id),
    encounter_date TEXT NOT NULL,
    encounter_type TEXT NOT NULL,
    summary TEXT NOT NULL
);

CREATE INDEX idx_encounters_by_record ON encounters(record_id, encounter_date DESC);

CREATE TABLE care_team_memberships (
    clinician_id TEXT NOT NULL REFERENCES users(id),
    record_id TEXT NOT NULL REFERENCES records(id),
    episode_of_care_id TEXT NOT NULL,
    status TEXT NOT NULL CHECK (status IN ('active','ended')),
    start_date TEXT NOT NULL,
    end_date TEXT,
    PRIMARY KEY (clinician_id, record_id, episode_of_care_id)
);

CREATE INDEX idx_care_team_by_clinician_record
    ON care_team_memberships(clinician_id, record_id, status);

CREATE TABLE clinical_notes (
    id TEXT PRIMARY KEY,
    record_id TEXT NOT NULL REFERENCES records(id),
    author_user_id TEXT NOT NULL REFERENCES users(id),
    author_display_name TEXT NOT NULL,
    author_role TEXT NOT NULL CHECK (author_role = 'clinician'),
    created_at TEXT NOT NULL,
    note_type TEXT NOT NULL
        CHECK (note_type IN ('progress','assessment','plan','observation','discharge_summary')),
    body TEXT NOT NULL CHECK (length(body) BETWEEN 1 AND 8000),
    encounter_date TEXT NOT NULL CHECK (date(encounter_date) <= date(created_at))
);

CREATE INDEX idx_notes_by_record_chrono ON clinical_notes(record_id, created_at, id);

CREATE TABLE audit_entries (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    record_id TEXT,
    accessor_user_id TEXT NOT NULL REFERENCES users(id),
    accessor_user_display_name TEXT NOT NULL,
    accessor_role TEXT NOT NULL
        CHECK (accessor_role IN ('clinician','patient','compliance_officer')),
    timestamp TEXT NOT NULL,
    operation TEXT NOT NULL CHECK (operation IN ('read','append','list')),
    outcome TEXT NOT NULL CHECK (outcome IN ('permitted','denied')),
    authorisation_basis TEXT NOT NULL
        CHECK (authorisation_basis IN (
            'care_team_member','not_care_team_member','patient_own','patient_other',
            'compliance_role','outsider','record_not_found'
        )),
    originating_ip_address TEXT NOT NULL
        CHECK (length(originating_ip_address) BETWEEN 7 AND 45),
    note_id TEXT,
    CHECK (
        (operation = 'append' AND outcome = 'permitted' AND note_id IS NOT NULL)
     OR (operation = 'append' AND outcome = 'denied' AND note_id IS NULL)
     OR (operation IN ('read','list') AND note_id IS NULL)
    )
);

CREATE INDEX idx_audit_by_record_chrono ON audit_entries(record_id, timestamp, id);
CREATE INDEX idx_audit_by_user_chrono ON audit_entries(accessor_user_id, timestamp, id);
CREATE INDEX idx_audit_chrono ON audit_entries(timestamp, id);
```

## How invariants map to storage

| Invariant (from spec)                                                       | Where enforced                                                                                                                                       |
|-----------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------|
| FR-001 / SC-009 authentication boundary                                      | `server.py` boundary: bearer-token resolution via `tokens` table before dispatch; no audit entry on `401`.                                            |
| FR-002 / FR-003 single role + patient-record pairing                         | `users.role` CHECK + paired `assigned_record_id` CHECK.                                                                                              |
| FR-004 / SC-010 care-team-membership gating                                  | `permissions.can_access` runs the indexed SQL probe on every clinician-touching request; fail-closed on missing membership.                            |
| FR-006 patient self-access                                                   | `permissions.relationship` returns `PATIENT_OWN_RECORD` iff `user.assigned_record_id == record_id`.                                                   |
| FR-007 / FR-019 / SC-006 compliance content-blindness                        | `compliance_response.py` module structurally cannot access clinical-content tables; static + runtime probes.                                          |
| FR-008 / SC-003 byte-equivalent unauthorised response                        | Single `responses.forbidden_response()` helper at every refused code path; pinned `(status=403, content_type, content_length=47, body)`.              |
| FR-009 / SC-004 200ms p99 on the 403 path                                    | SQLite `timeout=0.15s` keeps the COMMIT within budget; perf probe in `test_perf_403_latency.py`.                                                      |
| FR-012 / SC-007 notes append-only                                            | No UPDATE/DELETE SQL on `clinical_notes`; schema CHECK `author_role = 'clinician'` excludes patient/compliance authors; no PATCH/DELETE routes.       |
| FR-013 / SC-001 / SC-002 always-on audit                                     | Audit INSERT in same transaction as every access decision; CHECK pairing on `(operation, outcome, note_id)` and `(operation, record_id)`.            |
| FR-014 audit-entry shape                                                     | Schema enumerates every required column with NOT NULL or CHECK; snapshot fields populated at INSERT time; IP captured from request.                   |
| FR-015 / SC-008 audit immutability                                           | No UPDATE/DELETE SQL on `audit_entries`. Static + runtime probes.                                                                                     |
| FR-016 / SC-005 1-second audit SLA                                           | `timeout=0.15s` on the connection (well within 1s); `OperationalError` → `503 service_unavailable` with rollback.                                     |
| FR-017 ≥7-year retention                                                    | No DELETE code path against `audit_entries`. Operational retention scheduling out of scope.                                                            |
| FR-018 compliance-officer endpoint filters                                  | `service.list_system_wide_audit` accepts `accessor_user_id`, `record_id`, `from`, `to`, `limit` (default 1000, max 10000); SQL ORDER BY `timestamp DESC, id DESC`. |
| FR-020 / SC-005 (URL-path PII) — record_id only in URLs                      | Routing in `server.py` uses `{id}` (= record_id); static probe `test_no_url_pii.py` forbids any path placeholder matching patient demographics.        |
| SC-011 valid IP on every audit                                              | NOT NULL constraint on `audit_entries.originating_ip_address`; CHECK on length sanity.                                                                |
